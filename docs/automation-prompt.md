# 定时任务设置

- 名称：七麦iOS分类榜单监测
- 项目：目标Mac克隆的本仓库目录
- 运行：独立任务、本地项目目录
- 时间：Asia/Shanghai每天02:00、05:00、11:00、17:00
- 范围：24个应用分类，三国双榜共144范围；不扫描游戏
- 更新既有任务时保留启停状态，暂停任务不自动恢复

## 可直接复制的任务描述

读取当前仓库AGENTS.md，执行本仓库的 `$ios-rank-monitor`，使用本机持久化项目目录，不新建worktree。固定入口为python3 scripts/monitor.py。先doctor，再start登记或领取轮次，之后检查内置浏览器和登录并读取实际工具文档。start若skipped=true，说明当前轮仍有执行者，结束此次触发，不修改旧轮、不发邮件；若resumed=true，继续返回的同一runId，不另建轮次。按scanFamilies仅采集七麦美德日iPhone的24个应用分类，免费榜和畅销榜各完整前80，共144范围，不扫描游戏。时间为北京时间每天02:00、05:00、11:00、17:00；修改任务描述保持原启停状态与其他设置。每范围立即ingest，明确缺数或单项失败立即mark。当前新轮次按latest_valid_scope_v1，每个国家/设备/大类分类/榜单独立从本轮之前正式归档中找最近兼容完整前80；上轮失败、缺数或不兼容可向前找，不设回溯期限。整轮部分完成的完整范围可用，正式/测试隔离；本轮缺数不能填旧数据。程序登记时固化baselines.json及manifest摘要，代理不得手选或更换基准。previousRunId只表示上一执行轮。基准或历史完整归档损坏应报告存储异常，不静默回溯。未知不等于零；没有兼容基准时建立该范围基线并说明覆盖。历史游戏和旧轮次原比较及入选结果保留。

排名保存后，对带releasePolicy的新轮次调用prepare-release，由程序计算新进候选、复用已核实缓存，并返回按国家＋App ID去重的待补查清单。仅用内置浏览器访问pending中的详情页，按仓库网页流程执行assets/read-qimai-release.js，读取真实URL、可见App ID、所选国家及明确标注的“最早发布”，合并真实observedAt后逐项ingest-release。不能使用版本更新日期替代。主列表仅保留“免费榜或畅销榜新进前80，且最早发布在本轮北京时间参考日最近6个自然月内”的已核实App，包含边界日；日期未知、失败、晚于参考日单列待核实，不能放入主列表，也不能算作超过六个月。完整榜单继续保留前80；旧轮次不补查、不改写原入选结果。HTML新进视图支持最近6、5、4、3、2、1个月发布筛选，默认6个月。

新浏览器轮次executionPolicy=completion_v1，取消90分钟硬截止，尽可能完成本轮所有可执行项；先完成榜单处理，再完成发布日期核实。来源日固定为本轮开始时的北京时间日期，使用start/resume返回的sourceDate。跨天恢复必须通过公开日期控件选择该日并校验真实DOM日期，不用今天榜单填昨日缺口，不猜私有日期接口。源站明确不再提供该日才mark source_no_data，附本轮sourceDate及可见原因；不确定时保留失败或阻塞。发布日期可跨天继续，六个月准入仍用本轮固定参考日。

每个榜单范围、每个日期补查初次尝试加最多2次重试，次数持久化、resume不清零。单项榜单failed传唯一attemptId，重发同一失败使用原ID；不能伪造尝试耗尽次数。必要时用本地凭据正常登录；验证码、短信/扫码、二次验证、风控、全局网络或浏览器工具受阻时suspend记录原因及人工动作，保留running等待续跑，不批量标失败、不finalize、不发最终邮件。不要绕过验证。平台/会话中断后由后续触发或手动start恢复，不声称外部平台永不中断。仅用户明确取消才abort，不得作为日常兜底。

工具重置后用本次执行令牌resume同run，先处理pending，再prepare-release恢复日期进度。执行权租约15分钟，每次保存、resume、progress续约，长浏览器操作前后及时续约；租约过期使本轮可由start接管并轮换令牌，接管必须通过start；尚未被接管时原令牌仍可续约。租约不触发归档。旧执行者收到令牌不匹配应停止，不读取新令牌争抢。下一定时时点优先恢复或等待当前轮，恢复完成后等下一正常时点开新轮，不在同一次触发再start、不补造错过时点。日常不自行修改程序、配置或规则。数据、凭据、日志、截图和报告不提交、不推送；仅下述邮件按本地配置发送，不向其他应用外发。

每阶段读取progress：仍有可执行排名/日期就继续，只有canFinalize=true才finalize。程序拒绝提前归档；单项重试耗尽或有证据的缺数可部分/失败归档，处理完成不等于数据齐全。未核实日期保留待核实，未知不算已排除。渲染失败用render离线恢复缺失产物，不重采集；已封存report-data.json直接复用，已有历史单轮报告不重写、不重算，已完整包含归档轮次的日期页保留；中断导致日期页缺轮时用封存数据补齐。历史封存JSON丢失或损坏需恢复原文件，不能重算覆盖。完成消息给出排名候选、已确认入选、超过六个月排除、日期待核实、完整/可比较范围、回溯范围、无历史基准/本轮缺数、缺失原因及报告位置。各触发榜单分别显示基准运行、来源日期、基准及本轮实际采集时间和实际跨度；只能说明两个观测端点的差异，不宣称固定三小时新进或首次入榜时间。全局阻塞的未归档轮次仅说明runId、进度和恢复动作，不虚构完成或报告。旧轮无executionPolicy保留原生命周期，历史不重算。规则以仓库和每轮固化证据为准，不依赖旧聊天。

本轮正式browser轮次封存后，显式执行python3 scripts/monitor.py mail-send RUN_ID，RUN_ID只能是本轮真实编号。按.local/mail.json及权限600的.local/mail-secrets.json发送QQ SMTP邮件，零入选、基线、部分完成和失败也发送运行摘要；正文含全部已确认入选App及七麦详情链接，日期待核实只列摘要数量。未配置或disabled明确跳过，不代填收件人、不读取输出授权码、不自行开启发送。只报告脱敏收件人与发送结果；submitted仅表示服务器已接受，不承诺进入收件箱。partial/failed只允许显式补发失败项，unknown需人工核对、停止自动重发，busy不干扰正在发送的进程；不删除发送记录，不扩大重试。邮件失败不改动本轮结果、不重采集；finalize/render/import本身不发信，渲染失败但封存成功仍可单独执行mail-send。测试/旧版导入/进行中轮次不发信；重复启动被跳过则不发信，不遍历历史补发。

无排名比较依据时，报告和完成消息中的数量显示0，同时说明基线、缺数或待比较范围；原始结果保留未知状态。已有排名候选但日期全部未知时仍显示待核实。

最终完成消息必须提供“打开本轮报告”和“历史总览”的可点击Markdown链接，分别指向本轮实际生成的`data/YYYY-MM-DD/runs/<runId>/report.html`和`data/index.html`。链接使用当前仓库的绝对文件路径，输出前确认文件存在，不能只写路径文本。本轮报告入口会跳转到日期筛选页并选中对应采集时点，用户点击即可查看；具体打开方式由桌面应用决定，不承诺强制使用外部浏览器。部分完成或失败归档也提供本轮入口；报告未生成时明确说明原因，不虚构链接。重复启动被跳过时明确说明未产生新报告，不将已有轮次说成本轮结果。
