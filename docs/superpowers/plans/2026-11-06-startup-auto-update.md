# 启动前受控同步实施计划

按superpowers:executing-plans执行，用户已授权实施；不自动推送。本计划依据已确认方案：先完成旧轮，两组全局空闲才更新；同步失败继续当前本地版本并说明。应用/游戏规则、目录、邮件配置和任务启停状态保持。

1. 本地稳定启动器：scripts/launcher.py安装为.local/monitor-launcher.py，原子安装、不覆盖已有update.json。startup持全局排他锁，command持共享锁；通过继承FD执行仓库脚本。config/update.example.json提供默认关闭的部署配置，安装显式开启本机同步。无新依赖。
2. scripts/update_start.py只用标准库：验证配置/工作区/分支，检查两组正式及测试未结束轮次、取消恢复标记和中断更新状态；有旧轮延期。fetch指定main，仅快进，拒绝data/.local等受保护路径。候选Git归档在data/updates临时目录校验语法、双组doctor和完整测试，通过后才merge；更新中断留下applying标记并阻止盲目续跑。失败不强制reset/stash/clean。
3. 更新后新进程检查并start本组，在同一锁下登记轮次；启动JSON和data/updates审计记录同步前后SHA、状态/原因及本轮编号，不泄露令牌。新轮记录完整codeCommit，续跑拒绝代码版本不一致；旧无字段记录继续兼容。monitor直接入口也先取得共享锁再导入程序。
4. 测试用本地临时bare远程与合成项目，覆盖开关、无更新、有效更新、校验失败、网络失败、脏工作区、分叉、双组旧轮、损坏索引、锁并发、中断标记、版本固定与凭据/数据保护。完整回归及一次独立最终审查。
5. 更新AGENTS/README/skill/部署和命令说明，将两份任务模板改为薄启动描述，最新业务步骤移至run-apps/run-games。本机安装稳定启动器并开启本地更新配置，保留两条任务暂停及其他设置。仅离线检查本机，不启动正式采集或SMTP。

审查重点：全局锁的继承/释放与原子登记、跨组未完成状态、候选校验与激活失败、配置错误/凭据日志、首次部署与旧轮兼容。分阶段观察RED/GREEN；审查发现的重要问题统一修复后全量复测。
