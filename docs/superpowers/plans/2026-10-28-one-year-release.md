# 首次发布准入改为一年

用户要求：把App入选首次发布范围从半年改成一年，分析后实施。沿用固定北京时间参考日及自然月计算，回溯12个月、含边界；排名比较不变。

1. 新配置使用qimai_first_release_12_months_v1、months=12，生成1～12个月界限；支持旧6个月版本。准入、Markdown、邮件按本轮固化月份取界限，不硬编码6。未知/未来日期仍待核实。
2. HTML新轮默认12、支持1～12；旧6月轮仅1～6。切换准入周期重设为该轮最大月份；同周期筛选保留用户选择。混合6月/12月或无日期规则时禁用月份筛选并说明，保留各轮原入选结果；完整榜单不筛日期。
3. 不重算历史、不补查或补发旧轮；旧日期缓存可复用，新范围只影响新轮次。同步技能、接口、README/部署、任务描述及技能卡片，保持实际任务状态和其他设置。
4. 补日期/闰年、6～12个月与12月边界、超过一年、未知与未来、缓存/排名连续、旧新混合及UI实际脚本筛选、报告邮件范围、历史哈希测试。完整测试后独立审查并核对任务设置；不启动真实采集/邮件或自动提交推送。

审查重点：默认页面不能隐藏7～12月入选项；老政策边界/旧结果保持；混合轮次不错误延伸半年规则；月份切换无非法索引；固定参考日不受浏览器当天日期影响。
