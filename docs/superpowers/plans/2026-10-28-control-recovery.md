# 正式/测试令牌隔离与取消恢复

依据：用户同意修复只读复核中复现的两项缺口，业务规则、历史报告、任务暂停状态保持。

1. 新令牌按模式及运行编号分路径保存，manifest标记tokenVersion。兼容唯一旧令牌并安全迁移；旧同编号令牌无法判属则拒绝授权，通过各模式start按原租约接管。新模式令牌缺失不得回退共用路径。CLI编号同时存在两种模式时要求显式mode。
2. 人工取消先保存cancelling状态及原因/时间，再归档。任何采集、日期补查、suspend均不得撤销取消。start/resume/finalize只完成取消归档，本次恢复不新建轮次；旧running+abortReason亦识别为取消意图。并发仍由原模式文件锁串行化。
3. 保留终态partial/failed并标cancelled，报告/邮件明确人工取消与原因；取消成功后重复abort幂等，可恢复中断的报告生成。取消的active标记保留到报告及清理成功，终态后残留标记的start只恢复原轮报告/清理，不重写封存结果或新建轮次。取消未封存不渲染/发信。历史只读；不自动收集或发送。
4. 测试：同编号双模式、交叉令牌拒绝、原令牌继续有效、权限、旧令牌迁移/歧义/丢失、CLI显式模式；取消各写入阶段中断、旧标记、配置变化、各恢复入口、阻止继续采集、重复取消、报告转义与渲染失败恢复。完整测试及独立审查。
5. 同步技能/命令/部署/任务说明，任务维持暂停及时点，检查历史哈希。不自动提交或推送。
