# 首次发布准入与1～6个月筛选实施计划

用户已确认：七麦“最早发布”；6个自然月且包含边界；参考日为本轮开始的北京时间日期；未知单列；新规则仅新轮次；月份筛选仅用于新进App；同时修复三项异常恢复问题。

## 实施顺序

1. 回归测试先复现残留启动标记、截止时间被lease延后、成功后失败原因残留，再修复并运行完整测试。
2. 保留完整前80和相邻排名比较。新增独立上线策略、日期处理模块、prepare-release与ingest-release；按国家＋App ID缓存并逐轮固化证据，未知不入选，旧轮次不回填。
3. 在离线报告中增加最早发布、排除/待核实统计和1～6个月筛选。完整榜单、历史和混合规则视图禁用月份筛选，保留原结果。
4. 同步技能、接口、浏览器流程、README、部署和定时任务描述；先登记再检查登录，先榜单再补日期，共用固定90分钟窗口。
5. 运行日期、业务、缓存/恢复、转义和页面交互测试；独立审查；核对真实网页样本并完成一轮正式新规则采集。确认旧历史不变，再恢复原四个时点的任务。

## 公共接口

`python3 scripts/monitor.py prepare-release RUN_ID --token TOKEN`准备缓存并返回待查候选；`ingest-release`以JSON接收日期证据或失败原因。状态verified/unavailable/failed；必须记录范围、来源URL、标签、原文、核实时间。历史运行没有releasePolicy时仍按v1排名规则展示。排名指纹不因上线准入改变。
