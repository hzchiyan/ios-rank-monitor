# 完成驱动与中断续跑

依据：用户确认取消90分钟硬截止，优先完成当前轮次；跨天保持来源日，日期核实继续。保持任务启停状态，不启动采集或发信。

1. 为新浏览器轮次记录 `executionPolicy: completion_v1`；旧记录和旧版导入保留原行为。新轮次无总截止时间，采集时间真实，榜单来源日等于固定参考日。
2. 持久化排名重试、日期重试、阻塞原因。全局受阻使用 suspend；后续 start 优先领取同轮。15分钟无心跳仅释放执行权，领取时轮换令牌，旧执行者不得写入。每次保存/恢复更新心跳。
3. 排名处理完成后核实日期；pending/progress 给出可执行项。finalize 拦截未处理范围、可重试失败、日期可执行项及全局阻塞；重试耗尽或有来源证据的缺数可部分归档。人工明确取消才使用 abort。
4. 补齐模拟时钟、跨天、并发领取、幂等、断点恢复、提前归档、日期补查、旧版兼容和CLI测试。
5. 同步仓库技能、接口、部署、README、任务模板和既有定时任务，保持原时点及暂停状态。运行全套测试，核对历史不变，执行一次独立审查。

审查重点：跨进程令牌隔离、归档原子恢复、参考日期、未知与零、相邻比较、邮件仅封存后发送。浏览器历史日期可用性依赖公开界面，不假设私有日期接口；浏览器/平台中断靠下一次触发续跑，不能承诺平台永不停止。
