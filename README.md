# iOS 榜单监测

可克隆到其他Mac的Codex项目技能。Codex用本机内置浏览器读取七麦网页，Python工具校验比较，生成本机归档的Markdown与可筛选HTML报告，可选通过QQ邮箱发送本轮报告。

## 固定口径

| 项目 | 规则 |
|---|---|
| 范围 | 美国、德国、日本；iPhone；24个应用分类，不扫描游戏 |
| 榜单 | 免费榜、畅销榜，各完整前80，共144个范围 |
| 时间 | 北京时间每天02:00、05:00、11:00、17:00 |
| 排名候选 | 免费榜新进前80 **或** 畅销榜新进前80 |
| 新规则入选 | 排名候选 **且** 七麦“最早发布”在本轮参考日最近12个自然月内（一年，包含边界日） |
| 比较 | 每个国家、设备、大类/分类、榜单最近一次兼容且已归档的完整前80；不设回溯期限 |
| 去重 | 同国家、同分类、同App合并触发；跨分类、国家、时点分别保留 |
| 缺数 | 上轮缺数可向前寻找有效基准；本轮缺数或无兼容历史时待比较，数量显示0并说明覆盖 |

首次建立基线。前次不在前80，不能推断具体旧名次。本项目不输出实际下载量或下载量估算。

`scanFamilies:["应用"]`控制采集范围；缺少该配置仍为应用与游戏。完整40分类目录保留，供历史游戏展示和旧版导入使用。当前配置comparisonVersion=latest_valid_scope_v1，新浏览器轮次按各范围从本轮之前的正式归档逆序寻找最近兼容完整快照。国家、设备、排名规则、前80门槛、时区及分类定义必须一致；整轮部分完成不妨碍其中完整范围使用，日期核实失败不影响排名快照。失败、缺数和不兼容范围跳过，无期限限制；历史存储损坏明确报错，不能伪装成普通缺数。测试历史严格隔离。

登记时将每范围基准编号、来源日期、实际采集时间、快照摘要和跨过轮数固化至baselines.json，manifest保存校验摘要；恢复、候选、日期核实和归档均复用。previousRunId仅表示上一执行轮，实际比较基准可能各不相同。免费榜/畅销榜各算新进后合并，继续首次发布准入，当前新轮为12个月。报告与邮件显示实际跨度和回溯范围；只能描述两个观测端点的差异，不能推断中间变化、首次进榜时间或固定三小时增长。跨轮可能再次触发，不新增永久通知去重。

新规则只影响新轮次。旧shared_scopes_v1继续严格相邻；没有比较版本的旧轮继续整体配置指纹比较。缺少comparisonVersion配置时新轮仍默认shared_scopes_v1；旧版导入保持旧规则，其兼容完整快照可被新轮用作基准。旧报告不重算，但新轮可复用已有合法历史。

无排名比较依据时，页面和文字报告的数量统一显示0；原始结果仍保留未知状态，基线、缺数和待比较范围在覆盖说明中展示。排名候选的发布日期全部未知时，入选数量继续显示“待核实”。

上线日期取七麦详情页明确标注的“最早发布”，不是版本更新日期，也不宣称等于目标国家首次上架日期。参考日固定为本轮开始时的北京时间日期；例如2026-10-28回溯12个月得到2025-10-28；一年按12个自然月计算，不固定为365天，闰年2月29日回溯一年取目标年2月最后一天。日期缺失、解析失败或晚于参考日的候选单列待核实，不进入主列表。完整榜单仍保存全部前80。

新配置采用releasePolicy.version=qimai_first_release_12_months_v1、months=12；旧qimai_first_release_6_months_v1继续按6个月处理。新规则只作用于启用后的新轮次。历史运行和旧版导入保留原规则；排名基准的有效性不依赖上线准入结果。已核实日期按国家和App ID缓存，每轮固化所用证据，重建旧报告不使用后来缓存改写结果。

## 新电脑开始

1. 准备macOS、Git、Python3.11+、已登录的Codex桌面应用和内置浏览器控制能力。
2. 克隆仓库，在Codex中作为本地项目打开，不需要创建者的聊天记录。
3. 在新会话输入：**请按本仓库部署说明初始化并运行监测。**
4. 按[部署指南](docs/deployment.md)检查环境、核实浏览器与账号，试跑后配置目标机任务。

```sh
python3 scripts/monitor.py doctor
python3 -m unittest discover -s tests -v
```

程序检查不能证明浏览器、账号或定时任务可用。[项目技能](.agents/skills/ios-rank-monitor/SKILL.md)和[任务描述](docs/automation-prompt.md)均随仓库保存。

## 本地报告

```text
data/
  state.json                         # 正式任务顺序和相对路径
  release-cache.json                 # 已核实最早发布日期缓存，按国家和App ID分开
  index.md / index.html              # 日期总览
  YYYY-MM-DD/
    index.md / index.html            # 当日时点和离线筛选
    runs/<runId>/
      manifest.json                  # 状态、版本、比较轮次
      snapshots.jsonl.gz             # 一份压缩快照
      baselines.json                   # 新比较版本固化的逐范围基准，摘要保存在manifest
      releases.json                  # 本轮日期证据与缺失原因，结束后不可修改
      report-data.json / report.md
      report.html                    # 打开该时点的日期筛选页
      checkpoints/                   # 运行中分片，归档后清理
  test/                              # 测试历史，不影响正式基线
.local/
  credentials.json                   # 可选本地凭据，权限600
  tokens/formal/<runId>              # 正式操作令牌，权限600
  tokens/test/<runId>                # 独立测试操作令牌，权限600
```

完成一轮后，点击完成消息中的“打开本轮报告”或“历史总览”，也可用Finder打开`data/index.html`。HTML支持日期、时点、国家、大类、分类、榜单、关键词与最近1～12个月发布筛选，切换新进App和完整榜单。上线月份仅用于新进列表：一年轮默认12个月、可选1～12，旧半年轮默认6个月、只提供1～6；切换周期重置到该轮最大月份，同周期内保留用户筛选。完整榜单每次看一个时点、一种榜单，保留全部前80。混合半年/一年或无日期规则轮次时禁用月份筛选，保留各轮原入选结果，并提示选择相同准入周期的时点。

大类和分类选项来自所选轮次的实际计划范围：仅应用的新轮次不提供游戏选项；旧轮次和包含旧轮次的汇总仍可筛选历史游戏数据。

HTML内嵌所需数据，无外网字体、CDN或本地JSON请求，无需服务器。单次HTML入口依赖同日期页，复制历史应复制整个`data`。render复用已封存report-data.json，不重算历史或重写已有单轮产物；日期页按HTML和Markdown实际包含的归档轮次检查，仅新增、缺失或中断未补齐时更新，完整旧日期页保留。缺少HTML/Markdown可用冻结数据重建；历史report-data.json损坏或缺失但已有报告时需恢复原文件，不能重新计算覆盖。首次封存尚未生成任何报告时允许完成首次生成。

GitHub仅保存程序、技能、说明和合成测试；`data/`、`.local/`被忽略，不自动推送。不要强制添加忽略文件。存储随四次全量采集增长，不自动删除历史。

## QQ 邮件报告（可选）

按[部署指南](docs/deployment.md#6-qq邮件配置与验收)配置本机`.local/mail.json`和权限600的`.local/mail-secrets.json`。默认关闭发送，QQ邮箱使用`smtp.qq.com:465`、SSL/TLS及SMTP授权码，登录账号与发件地址一致。实际配置和授权码不提交仓库，不放进聊天或日志。收件人支持多个地址，分别发送。

```sh
python3 scripts/monitor.py mail-check
python3 scripts/monitor.py mail-preview RUN_ID
python3 scripts/monitor.py mail-preview TEST_RUN_ID --mode test
python3 scripts/monitor.py mail-send RUN_ID
```

`mail-check`只做离线检查，不验证账号可用性；`mail-preview`不发信。正式任务在finalize封存后显式执行`mail-send`，每轮完整正文列出全部已确认入选App，名称可跳转七麦详情。零入选、基线、部分完成、失败也发运行摘要，日期待核实不混入入选列表。正文同时包含HTML和纯文本，无附件和本机文件链接。

仅正式、已封存的浏览器轮次允许真实发送；测试、旧版导入、进行中轮次禁止发送。`finalize`、`render`、导入本身不会发信，不自动补发历史。正文首次发送时固化，预览和重试复用；内容与按收件人发送记录位于本轮`mail/`目录。已提交成功的收件人不会重发；明确失败的收件人可再次显式执行`mail-send`重试。提交后断线、进程中断或提交后记账失败标为“结果不明”，停止自动重发，先人工核对。

未配置或禁用时明确跳过，不阻断采集；发送失败不修改排名、日期证据或比较链。服务器已接受不等于进入收件箱。仅连接建立前的临时网络失败自动重试一次，每次连接超时30秒；邮件网络等待使用独立锁，不占用采集锁，不影响续跑进度。任务仍保留原有启停状态。

## 能力边界

网页读取成功不等于自动登录通过。浏览器能力、账号权限、验证码、网页变化、目标机调度需要实际验证。短信、扫码、验证码或风控受阻时保留失败记录，要求人工恢复，不绕过验证、不自动购买会员。

新浏览器轮次使用`executionPolicy:completion_v1`，取消90分钟硬截止，以完成本轮可执行项为结束条件。先处理全部榜单范围，再为排名候选去重核实日期；还有未处理范围、可重试失败或日期待查时，程序拒绝finalize。每项初次尝试加最多2次重试，次数持久化；耗尽后明确缺失，日期未知仍列待核实，允许部分归档。完成处理不等于所有数据齐全。历史轮次和旧版导入保留原语义，`maxRunMinutes`仅供旧生命周期使用。

下一定时时点先用start检查当前轮次：仍有执行者则等待；已中断则恢复同一runId，不另建轮次、不覆盖已保存快照。执行权租约为15分钟，每次保存、resume或progress续约；长时间浏览器操作前后及时续约。租约过期使本轮可被接管，尚未接管时原令牌可续约，绝不自动归档；接管会轮换本地令牌，旧执行者不得再写。领取后的工具重置使用resume；失去执行权先start重新领取，不读取别的执行者令牌争抢。令牌按formal/test模式分目录；同编号两种模式并存时CLI要求显式--mode。唯一旧共享令牌可迁移并废弃旧文件；旧同编号令牌无法判属时拒绝授权，通过各模式start按原租约接管，不猜归属。全局登录、验证码、工具或网络不可用时suspend保存原因等待恢复，不批量标失败，不归档、不发最终邮件。只有用户明确取消才使用abort。取消先持久化为cancelling；中断后的start/resume/finalize只完成取消归档，返回cancelled=true，不继续采集、不在本次恢复另开新轮。取消恢复标记保留到报告生成及清理成功；终态后仍有同轮标记时，start只补报告和清理，不新建轮次、不改封存结果。取消报告明确原因；未封存取消不渲染或发信，封存邮件仍按原规则显式处理。

跨天继续使用本轮开始时的北京时间来源日；从公开日期控件选择该日并核对页面日期，不用今天的榜单填昨日缺口。源站明确不再提供该日时记录该日缺失，不能确认则保留失败/阻塞原因。发布日期核实可跨天继续，准入参考日不变。旧轮完成后等下一个正常时点才开新轮，错过的时点不补造快照。

电脑休眠、应用关闭、会话中断或平台限制仍可能停止当前执行；程序保存断点供下次定时触发或手动续跑，不能保证外部平台永不中断。电脑保持运行、联网，桌面应用保持打开。

本版本仅支持用户本地配置的SMTP邮件发送，不包含飞书、微信发送或网站托管。迁移验收方法见[部署指南](docs/deployment.md)。
