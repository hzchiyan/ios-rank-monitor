# 七麦榜单监测

从仓库根目录工作。范围以config/monitor.json和处理程序为准，不依赖个人技能或旧聊天。入口：`python3 scripts/monitor.py`。

## 初始化或部署

读仓库README.md和docs/deployment.md，完成程序检查、浏览器/账号检查、独立测试、正式手动运行，再在目标机配置任务。程序通过不等于浏览器或定时运行通过。新机无data则建立基线，有完整复制历史则延续。

## 执行采集

1. 运行doctor，读当前浏览器工具文档确认本机内置浏览器可用。正式任务先登记再检查登录，使登录失败也保留在正式比较链中。
2. start返回runId与令牌；被标skipped则结束，不干扰已有运行。小样本只用`start --mode test`。
3. 读[网页流程](references/browser-workflow.md)，用正常导航、滚动和只读DOM提取。pending列计划，每个完整范围立即ingest；明确无数据或失败用mark记录。不积攒全部数据后才保存。
4. 工具重置后resume同run读取进度，不新建替代轮次。每范围最多重试配置次数，超出本轮窗口则结束。
5. 无论完整、部分或登录失败，finalize归档更新报告。渲染失败保留已封存数据，用render离线重建，不重新采集或伪造成功。
6. 展示报告路径、新进数量、完整/可比较范围及失败原因。未知不能写0，不宣称全球同步瞬时快照。

## 固定边界

- 仅本机浏览器；缺能力报告，不换私有接口。
- 日常任务不改配置或程序；判断结果来自处理工具。
- 只比较上一正式任务，失败不删除，不回退更早基线。
- 真实输出全放data，凭据/令牌放.local，不上传。
- 登录受阻按部署说明处理，不绕验证码、权限或付费限制。

命令与输入见[接口说明](references/commands.md)。定时部署使用docs/automation-prompt.md，目标机手动和定时验收分别完成。
