# 七麦榜单监测

从仓库根目录工作。范围以config/monitor.json和处理程序为准，不依赖个人技能或旧聊天。入口：`python3 scripts/monitor.py`。

当前有apps（24个应用分类、144范围）和games（16个游戏分类、96范围）两个独立分组，美德日iPhone双榜前80及上线准入规则相同。每次任务固定一个profile，所有命令都带--profile apps或--profile games；未指定时仅默认apps，不跨组猜编号。时间均为北京时间02:00、05:00、11:00、17:00，两条任务分别执行，当前均保持暂停。更新既有任务时保留启停及其他设置。旧配置缺少profiles仍按原scanFamilies运行。

## 初始化或部署

读仓库README.md和docs/deployment.md，完成程序检查、浏览器/账号检查、独立测试、正式手动运行，再在目标机配置任务。程序通过不等于浏览器或定时运行通过。新机无data则建立基线，有完整复制历史则延续。

## 执行采集

所有阶段均遵守下方“命令失败与退出说明”；一次命令或工具失败不是本轮完成依据。

1. 确认本次profile，再运行带该profile的doctor后先start登记或领取正式轮次，再检查内置浏览器和登录；读本机工具文档。登录受阻也保留同一正式轮次等待恢复。
2. start返回runId与本次执行令牌。令牌按profile与formal/test分目录，应用保留.local/tokens/<mode>，游戏使用.local/tokens/games/<mode>，同编号并存的命令必须明确--mode，并保持本次--profile；旧共享令牌仅唯一归属可迁移，歧义拒绝，不猜测或手工复制。当前latest_valid_scope_v1在登记时固化每范围最近兼容的归档完整前80基准，不设回溯期限；处理程序保存baselines.json及manifest摘要，不由代理手工挑基准。cancelled=true表示已完成用户此前请求的取消归档，只报告取消结果和已有报告、按原归档邮件规则显式处理，不进入采集或再次start；resumed=true表示优先继续旧轮，不开新轮；skipped=true表示仍有执行者，结束此次触发、不修改旧轮或发邮件。租约15分钟只控制执行权，不是运行期限；保存、resume、progress续约，长操作前后主动续约。过期可由start接管并换令牌，旧执行者收到令牌错误应停止，不能读取新令牌争抢。小样本只用`start --mode test`。
3. 读[网页流程](references/browser-workflow.md)，用正常导航、滚动和只读DOM提取。pending列剩余可执行范围；每个完整范围立即ingest。来源日期必须等于start/resume返回的固定sourceDate，跨天用公开日期控件选择该日；源站明确不提供该日才mark缺数，不混入新一天榜单。单项真实失败用唯一attemptId记账，重发保留原ID。不积攒全部数据后才保存。
4. 榜单保存结束后，对带releasePolicy的新轮次调用prepare-release；程序计算新进候选、复用已核实缓存并返回按国家＋App ID去重的pending清单。只有pending中的App需要补查。首次基线或零候选不额外访问详情页。
5. 按网页流程读取每个候选详情头部明确标注的“最早发布”，使用assets/read-qimai-release.js取得真实URL、App ID、国家、标签、原文和日期，立即ingest-release。不能拿版本日期代替，也不按名次或名称推算。单项未知或解析失败用unavailable/failed并写原因；全局登录受阻转suspend。未知单列，不进入主列表。
6. 新轮次completion_v1取消90分钟硬截止。工具重置后resume同run，先处理排名pending，再prepare-release继续日期；跨天也继续核实，准入参考日不变。榜单和日期各初次尝试加最多2次重试，次数跨恢复保留。全局验证码、登录、工具或网络受阻用suspend记录原因，保留running、不归档、不发最终邮件；下一触发优先恢复。不能把一次全局阻塞批量消耗成全部范围失败。平台强制中断后由下一触发接续，不宣称平台永不停止。
7. progress确认canFinalize=true才finalize；有可执行排名/日期或全局阻塞时程序拒绝提前归档。单项重试耗尽、明确缺数可部分/失败归档，未知不等于零；仅用户明确取消才abort，不能作为自动兜底。取消意图持久化为cancelling；中断恢复只完成取消，不继续采集，progress取消中不能按普通待办处理。旧running+abortReason也按取消意图恢复；终态partial/failed带cancelled标记并显示原因。取消恢复标记保留到报告生成和清理成功；终态后残留同轮标记的start只补报告/清理并返回原取消结果，不新建轮次或重写封存内容。取消未封存不渲染、不发信。恢复旧轮完成后等下一个正常时点，不在同一次触发再开新轮。历史无executionPolicy的记录保留旧窗口语义，不重算。渲染失败保留已封存数据，用render离线重建。
8. 正式browser轮次封存后显式调用`mail-send RUN_ID`，仅使用本轮runId；零入选、基线、部分完成、失败也发送摘要及全部已确认入选App，详情可点击。未配置/禁用明确跳过，不能为发信擅自填账号或开启开关。submitted为服务器已接受；unknown/busy/failed/partial按返回结果如实报告，unknown先人工核对，不删除记录、自动重发或重新采集。测试和旧版导入不能发信。finalize、render、import本身不发信；渲染失败但已封存可单独发信。重复启动被跳过时不发信，不遍历补发历史。
9. 展示排名候选、已确认入选、超过一年排除（旧轮按其固化周期）、日期待核实、完整/可比较范围、回溯范围、无基准/本轮缺数及失败原因；按处理结果说明各榜单基准、实际采集时间和比较跨度，以及各收件人的脱敏发送结果。无排名比较依据时数量显示0，并说明基线或缺数及待比较范围；原始未知状态保留。已有排名候选但日期全部未知时，入选数量仍显示待核实。完成消息必须提供已存在的本轮report.html和本组总览（apps为data/index.html，games为data/games/index.html）的绝对路径Markdown链接，标题为“打开本轮报告”“历史总览”。跳过启动不虚构新报告，不宣称全球同步瞬时快照。

## 命令失败与退出说明

每次命令或浏览器工具返回failed、非零退出码、异常或无法解析的结果时，先读取可用的退出码、JSON错误及stderr，脱敏后判断下一步，不仅留下失败调用就结束对话。调用封装必须保留错误正文，不能让JSON解析或进程异常掩盖原始错误；不打印包含令牌的完整命令、异常对象或凭据。

| 失败类型 | 后续动作 |
|---|---|
| 单项页面不完整、导航或解析失败 | 按真实观察和剩余预算处理，以既有mark或ingest-release记录真实失败；重发同次尝试沿用原标识/证据。单项耗尽后继续其他pending，不结束整轮。 |
| 参数、JSON或命令调用格式错误 | 修正调用格式再提交；不修改真实页面字段来通过校验，不将调用错误当作新增采集尝试。原网页失败尚未记账时补录同次尝试，不虚构次数。 |
| 全局登录、浏览器工具或网络受阻 | 仍持有执行权且本地命令可用时suspend；确认返回成功后才能说阻塞原因已保存。保留同一轮次等待恢复，不批量耗尽重试、不强行finalize。 |
| 令牌不匹配、执行权已丢失 | 停止所有写入和续租，包括mark、suspend、progress；说明失去执行权，不读新令牌争抢，由合法执行者接续。 |
| 配置不兼容、基准/历史损坏、磁盘写入失败 | 保留现场，不擅自改配置、删文件或换基准。能安全记录阻塞时记录；写入仍失败时直接说明未能落盘及所需恢复动作，不能声称已暂停或已保存。 |
| 已归档轮次的渲染或邮件失败 | 按原render或邮件规则恢复，不suspend、不重新采集/归档，不占用采集重试预算；邮件unknown先人工核对，不能自动重发。 |

批量读取以单项为异常边界：一项失败不能让其余项目无处理地丢失。若整个批次抛错或提交结果不明，仍有执行权且本地命令可用时先读取progress/pending，对照已有快照和日期记录再继续；不假定整批成功或失败，不重复覆盖成功数据。重发保留同次尝试的标识/证据；无法确认或记账失败时说明进度不确定，不能另造尝试来绕过预算。仍有可执行项且未整体受阻时继续工作；finalize仅按原canFinalize规则，不将报错作为提前归档理由。

每次可控退出必须给文字说明，覆盖正常归档、全局受阻、失去执行权、无法写入、取消恢复、跳过启动及启动检查失败：写明runId（未取得则明确未取得）、失败阶段和国家/分类/榜单或App、脱敏错误、最后可信的已完成/剩余进度、保存或暂停是否成功、归档状态及恢复方式。未知数量明确未知，旧进度标明是最后一次确认值；未归档不冒充完成、不发最终报告邮件、不虚构报告链接。无法调用progress或suspend时也必须说明失败，不能声称已成功保存；已有数据与本次错误记录是否保存分别说明。正常归档继续按步骤8、9发信和给出真实链接。

若平台直接终止执行，内部总结可能来不及产生；下次合法恢复先核对持久化进度并说明前次中断，不能声称配置保证永不中断。

## 分组、浏览器和历史继承

apps保留data/及data/test/，games使用data/games/及data/games/test/；索引、当前轮、锁、令牌、日期缓存、报告、邮件正文和投递记录独立。共用.local/credentials.json、mail.json和权限600的mail-secrets.json，不复制授权码。两组各自封存后分别发送一封报告，主题标明应用或游戏；一组邮件失败不重采集另一组。

两条任务各建并持有自己的浏览器标签页，不接管、导航或关闭另一组的标签页；不依赖另一任务的JS变量、runId或令牌。单组失败或取消仅处理本组；共享登录、浏览器或网络整体受阻时按本组失败流程如实suspend，不声称资源完全隔离。

游戏由程序在登记时只读查找本组历史和早于本轮的旧应用历史中的兼容游戏快照，选择最近有效完整基准。baselineProfile注明apps（应用历史）或games，skippedRuns只计算本组跨过的轮次，实际跨度仍以采集时间计算。来源分组、运行编号和摘要共同冻结，代理不能手动迁移、复制成新观测或换基准；没有兼容数据才建立基线。旧应用/游戏混合报告不重写、不迁移到新入口，游戏新轮不进入应用索引。

## 上线准入与历史

当前新轮采用qimai_first_release_12_months_v1：“免费榜或畅销榜新进前80，且最早发布在本轮北京时间参考日最近12个自然月内（一年）”，包含起止边界；一年不是固定365天，月份/闰年边界由程序计算。HTML新轮默认12、可进一步选最近1～12个月，仅作用于新进App。完整前80不删行。旧6月版本保留6个月准入及1～6筛选；混合半年/一年或无日期规则轮次禁用月份筛选、保留各轮原入选结果，提示选相同准入周期。旧轮不补查、不重算、不按一年回填，也不补发旧邮件；已核实日期缓存可按新轮参考日复用，排名基准及去重不变。

## 固定边界

- 仅本机浏览器；缺能力报告，不换私有接口。
- 日常任务不改配置或程序；判断结果来自处理工具。
- 新轮latest_valid_scope_v1逐范围找最近兼容、已归档的完整前80；上轮失败/缺数/不兼容可继续向前找，不设年龄上限。整轮部分完成的完整范围可用，正式与测试隔离，本轮缺数不填旧数据，失败轮仍留在执行链。
- previousRunId只表示上一执行轮。免费/畅销榜可用不同基准；实际跨度以该范围两次capturedAt计算，仅表示两个观测端点差异，不宣称固定时长新进或首次入榜时间。基准已固化后不得重选；文件缺失、损坏或摘要变化应报告存储异常，不能静默回溯更早快照。
- 旧shared_scopes_v1和无版本轮次保留原比较方式；不重算历史报告、不重发旧邮件。render复用已封存report-data，只为新增或缺失产物生成页面；已有单轮报告及已完整包含归档轮次的日期页不重写；中断导致日期页缺轮时从封存数据补齐。缺失历史冻结结果需恢复原文件。
- 真实输出全放data，凭据/令牌放.local，不上传代码仓库。仅允许邮件功能按本地配置向目标邮箱发送报告，不通过其他应用外发；授权码不进日志或聊天。
- 登录受阻按部署说明处理，不绕验证码、权限或付费限制。

命令与输入见[接口说明](references/commands.md)。定时部署分别使用docs/automation-prompt.md（apps）和docs/automation-games-prompt.md（games），目标机手动和定时验收分别完成。
